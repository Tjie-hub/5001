- **Comparison:** corpus `open` vs the 09:00 minute bar's `price`. That bar is the last print of the
  first minute, not the auction print, so an exact match is not expected; the comparison is

| group | n | 09:00 = open | within 1 tick | median dev (ticks) | p90 dev (ticks) |

## 2 · X1 driver — blocking defects (B1–B5)

**B1 · Look-ahead in the IHSG leg** (`screen_x1_overnight.py` l.180–190). `x` is a Series indexed
`cal[1:]`, and the pairs read `x.iloc[j−1]`, which is the value stamped `cal[j]` = **D**. Under any
alignment of `jk` onto `cal`, that is `JKSE close(d) → close(D)`. **Day D's close is after the
outcome window (open(D) → close(D)).** R_D = y − β·x_D therefore subtracts part of the outcome and
builds in a mechanical negative slope. The spec requires `close(d−1) → close(d)`, i.e. stamps
`cal[j−2]`, `cal[j−1]`. The same defect applies to the FX leg (`fx.reindex(cal[1:]) /
fx.reindex(cal[:-1])`).

**B1b · Misalignment / crash.** `jk.values[1:] / jk.values[:-1]` uses the raw ^JKSE series (8,883
returns from 1990) and is **not reindexed to `cal`**. As written, `np.where` cannot broadcast and the
driver crashes. The obvious "fix" (`reindex(cal)`) reproduces B1 exactly. So implement the leg
explicitly by date: for D = cal[j], with d = cal[j−1] and d₋₁ = cal[j−2], use the values **stamped d
and d₋₁**.

**B2 · FX leg inverted, in TIMING.md §3 l.38 and the driver.** `USDIDR=X` is IDR per USD (17,928
on 2026-10-05). The JKSE level in USD is JKSE/FX, so
`r_JKSE,USD = (JKSE_d / JKSE_{d−1}) · (FX_{d−1} / FX_d) − 1`.
TIMING.md and the driver both multiply by `FX_d / FX_{d−1}`. Amend TIMING.md, the predeclaration's
signal line and the driver. The TLKM-USD leg for the TLK arm gets the same correction. Check
`fetch_jisdor.py` / any JISDOR use for the same convention.

**B3 · Run guard.** Replace the substring test with an exact, hash-bound line. The driver runs only
if a `REVIEW_R2*.md` contains the line
`R2-DECISION: X1 GO driver_sha256=<sha of the re-frozen driver> predeclaration_sha256=<sha>`
and both shas equal the files on disk.

**B4 · Empty book ≠ zero return** (`book()`, l.133–142). `np.nansum` returns **0.0** on days with no
eligible member, and those zeros enter the regression as real observations. Set them to NaN when
the day's weight sum is 0. Disclose the count per split; early discovery years with few
adv20 ≥ Rp 5bn names are the likely hits.

**B5 · k ≥ 4 exclusion is predeclared but not implemented.** `kcount` is computed and never used to
exclude anything. Implement it, and print the count excluded per split.

**Mandatory PIT tests**, committed with the re-freeze and run before the outcome run (they read no
outcomes):
- **(T1) Invariance:** perturb `open(D)`, `close(D)`, `JKSE_D` and `FX_D` by ±5% for a random 50
  sessions. Every `R_std` for session D must be bit-identical.
- **(T2) Timestamp assertion:** for every D, max(input stamp) < D for the IDX/FX legs, and every US
  close ≤ 08:45 WIB D under the DST-aware mapping in TIMING.md.
- **(T3) Sign check on a synthetic series:** IDR depreciation with a flat JKSE must give a
  **negative** USD return.

## 3 · Economics defects (non-gating, fix in the same re-freeze)

- **E1 · Abdi–Ranaldo reimplemented wrongly** (l.306–307). The driver computes
  `(c_t−η_t)(c_{t+1}−η_{t+1})`; the committed `cost_by_adv.ar_terms` correctly uses
  `(c_t−η_t)(c_t−η_{t+1})`. Call `cb.ar_terms` / `cb.ar_spread_from_terms` instead, and lag the term
  series so a day-D cost uses terms ending ≤ d−1 (the AR term at t needs η_{t+1}).
- **E2 · Unit error in the tick floor** (l.310). `np.maximum(ar_s, tickv)` floors a *fraction* at a
  *Rupiah* tick (1–25), so every spread is ≥ 100%. Use `tick_frac`.
- **E3 · Crash outside the try** (l.337). `cost_rt[cal[j], tl]` indexes an ndarray with a Timestamp,
  and `cost_rt` is undefined if the try block failed. Use `cost_rt[j, tl]` inside the guarded block.
  As written this would crash **after** the arms are computed but before RESULT is written, which
  violates the "crash only before outcomes" re-run rule.
- **E4 · Tick schedule.** The current IDX price-fraction schedule is applied to 2010–2021. Verify the
  historical schedules and apply the one in force on each date, or disclose that the current
  schedule was used and report the count of discovery-half name-days whose eligibility would flip.
- **E5 · Recorder correlation.** Confirm that the ledgers' `trades[].entry_date` key exists in all
  three schemas (FADE's top-level keys confirmed: `trades` is present). Otherwise the corr silently
  reads 0 days.

Minor, fix along the way:
- `beta.get(j−1)` / `sRd.get(j−1)` silently drop any day whose previous session lacked a pair. Use
  the latest β and σ from pairs **strictly before** j.
- The rolling windows take 251 points, not 250 (`i−250 … i`).
