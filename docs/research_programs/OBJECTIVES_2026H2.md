## 1. How to read this file

Objectives here **name mechanisms and evidence outcomes, never return targets** (PG-1). Under the N=1 ceiling, the terminal reachable tier this horizon is **C2** ([[RESEARCH_PROGRAM]] §9); objectives are set so the program can fully succeed *at that ceiling* while a parallel track works to lift it. Per PB-6, we **do not set success criteria the program is structurally forbidden to meet.**

Two programs are **Ready for Hypothesis Registration** with declared, merged families: **P-M · Microstructure Flow** (I5, I6, I7, I12) and **P-A · Auction Dislocation** (I2, I3, I8) — see [[RESEARCH_PROGRAM]] §2.

## 2. Objectives

### O1 — Initiate P-M and P-A on severe, admissible hypotheses

Move both programs from *ready* to *initiated* by registering the **first severe hypothesis** in each, drawn from the scored backlog (§3). Registration is the initiation event (G1 / T4). Each registered claim must clear the §6.1 admissibility gate of the parent — a named barrier, a blind mechanism, a test that can fail, effect > friction.
*Outcome:* ≥1 REGISTERED hypothesis per program, each honestly capped at C2, family joined permanently.

### O2 — Build the Failure Library as the primary cumulative research asset

> Build the Failure Library as the **primary cumulative research asset** by maximizing inexpensive early falsification (F1/F2) while preserving **complete experimental lineage**.

The objective is **scientific accumulation, not a target distribution.** We do not optimize toward an F1 histogram; we accumulate falsifications with unbroken lineage, and *let* the distribution reveal whether the institution is killing claims cheaply (§5.3 diagnostic). Every falsification carries exactly one defended F-mode (R1) and a complete receipt chain (HL-1). A refutation is a first-class product, equal in standing to a validated mechanism (R12).
*Outcome:* every experiment this horizon terminates in a lineage-complete Failure Library entry or a REGISTERED survivor — **none lost, none undocumented.**

### O3 — Produce at least one competent refutation (a mapped boundary)

Carry at least one hypothesis to a **defended refutation** — a competently refuted inefficiency entry. Per PG-11 this is a **program success, not a null result**: it maps a boundary of efficiency (the substantive object of study, §4.4) and adds a denominator every future program inherits.
*Outcome:* ≥1 entry in P-M or P-A moved to a defended FAILED with its F-mode and the boundary it maps recorded.

### O4 — Capacity track: advance the C3 unlock (G-8 / G-9) in parallel

The only way the C2 ceiling lifts is independent-review capacity. This horizon advances, without blocking O1–O3:

- **G-9 / RFC-1** — stand up an **OOS custody policy** so validation runs over custody-released partitions ([[CUSTODY_MODEL]] §5.1; [[RESEARCH_VALIDATION_FRAMEWORK]] §0). Until it exists, every E3+ claim rests on a control that does not exist.
- **G-8 / G-4** — secure **independent adversarial sign-off** capacity (a second, non-author reviewer). One non-author reviewer closes both the Phase-A sign-off (G-8) and the C1→C2 review capacity (G-4).

*Outcome:* RFC-1 drafted and the independent-review arrangement scoped, so the ceiling can lift mid-horizon **without redesign** of [[RESEARCH_PROGRAM]].

### O5 — Keep P4's timebox alive

P4 (Informed-Flow) is blocked on **LIM4** — history maturity (~3.5 mo). Time is the only remedy. Monitor history depth; when LIM4 clears, run the PG-A initiation packet with the timebox fixed ex ante (PG-14). **Do not initiate early to "get started"** — an under-matured history is a data deficiency, not a head start.
*Outcome:* a monthly maturity check (Wk-4 rhythm); initiation packet ready to fire the moment the history matures.

## 5. What "success" means for this horizon

Judged by [[RESEARCH_PROGRAM]] §8 metrics — **not** by profitability, Sharpe, CAGR, or win rate ([[RESEARCH_PROGRAM]] §1.1). This horizon succeeds if:

- Both programs are initiated on severe, admissible claims (O1).
- The Failure Library grows with **complete lineage and no lost experiments** (O2).
- At least one **competent refutation** maps a boundary (O3).
- The capacity track produces a **drafted RFC-1 and a scoped independent-review arrangement** (O4).
- **Zero X0** (no void/irreproducible claims) across the horizon.
- **A clean sheet of "no failures" is treated as an alarm, not a win** (R2/R12).

Full acceptance to C3+ is **out of reach this horizon by construction** (EV-9) and is therefore **not** a success criterion — it is objective O4's target for a *future* horizon.

## 6. Renewal rule

At horizon end, this file is **renewed, not redesigned**: create `OBJECTIVES_<next>.md`, carry forward unmet objectives, re-score the backlog, and update [[RESEARCH_PROGRAM]] §2/§9 **only** if the C2 ceiling has lifted (O4 landed) or a family milestone/termination changed program status. The standing machine is untouched. **If a renewal requires editing more than the objectives file, that is the signal to ask whether a real operational deficiency has appeared** — the only condition under which new governance is authored.
